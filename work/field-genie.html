An LLM agent for field network engineers

An agent that answers field engineers' troubleshooting questions from operating procedures and vendor manuals, and looks up alarm and site records for them.

Users
Field technicians, in a pilot
Stack
Azure AI Search, text-embedding-3-large, MCP tools, text-to-SQL, React
Languages
Bangla, English and Banglish

The problem

A technician at a site needs the right procedure and the right record quickly. The knowledge is spread across operating procedures, vendor manuals and alarm and site databases, and technicians write the way they speak, mixing Bangla and English.

What I built

Follow one made-up request through the system.

  1. Ask

    A technician types: "What alarms did SITE-0421 raise last night, and how do I clear the first one?"

    React front end; Bangla, English or Banglish

  2. Decide

    The agent works out that it needs live records and a procedure.

    LLM agent choosing among MCP tools

  3. Query

    It writes a database query for that site's alarms and runs it.

    Text-to-SQL on alarm and site records

  4. Look up

    It finds the procedure for that alarm in the manuals.

    RAG on Azure AI Search: ingestion, text-embedding-3-large embeddings, retrieval over SOPs and vendor manuals

  5. Answer

    It replies with the alarms it found and the steps to clear the first one.

    Answer grounded in the query result and the retrieved passages

How I built it

  1. Two kinds of knowledge, two routes. Procedures are documents, so they are retrieved. Alarms and site details are tables that change by the hour, so they are queried. One agent chooses between them.
  2. Tools over MCP. Text-to-SQL and the other tools reach the agent as MCP tools, so they can be reused by other agents and given only the access they need.
  3. A retrieval pipeline built end to end. Ingestion, embeddings with text-embedding-3-large and retrieval on Azure AI Search, measured with RAGAS.
  4. The technician's language first. Bangla, English and Banglish from the first version.
  5. Piloted with the people who use it. It went to field technicians as a pilot.

How it was tested

Retrieval was evaluated with RAGAS, and the agent was piloted with field technicians.

My part and the team's

I co-led the project and was one of two core developers. Field operations supplied the procedures and tested it on site.

Under the hood
  • Retrieval: ingestion of SOPs and vendor manuals, text-embedding-3-large embeddings, Azure AI Search.
  • Tools: MCP tools, including text-to-SQL on alarm and site records.
  • Front end: React.

What's next

Image and voice input, historical alarms and internal tools, predictive maintenance, and the move from pilot to production.
