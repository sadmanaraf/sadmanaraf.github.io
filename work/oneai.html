The HR assistant 1,300 employees can ask in Teams

A grounded HR-policy assistant inside Microsoft Teams, designed as the single governed entry point for HR, finance, IT, compliance and corporate-affairs services.

Scale

Launched on

Next version

Shape
One assistant where employees already work, built to become the front door for other functions

The problem

HR policy lives in long documents. Employees needed one governed place to ask, with an answer they could trace back to the policy. The same front door was designed to open later onto finance, IT, compliance and corporate affairs.

What I built

Follow one made-up question through the system.

  1. Ask

    An employee asks: "How many unused leave days can I carry into next year?"

    Copilot Studio agent in Microsoft Teams; in the next version, the internal employee app calling the service

  2. Sign in

    The service checks who is calling.

    JWT authentication

  3. Context

    The agent looks up what it needs to know about the employee to apply the policy.

    MCP server giving the Azure AI Foundry agent employee context

  4. Find

    It searches the HR policy documents for the passages that apply.

    Retrieval over the HR policy corpus

  5. Answer

    It answers from those passages and cites the policy.

    Grounding and citation behaviour

  6. Stream

    The answer appears word by word.

    SSE streaming from a FastAPI service on Azure Container Apps

How I built it

  1. Grounded, with citations. Answers come from the HR policy corpus and name their source. I owned the retrieval design and the citation and grounding behaviour.
  2. Launch where people already work. The first version went to the whole company inside Teams, on Copilot Studio over the policy documents in SharePoint.
  3. One front door. It was designed from the start as the single governed entry point, so agents for other functions could sit behind it.
  4. The next version as its own service. A Dockerised FastAPI microservice with JWT authentication and streamed responses, so the assistant can be integrated with the internal employee app. Semantic search, voice input, feedback capture and chat history were designed for this phase.
  5. Employee context through MCP. A separate server gives the agent employee context. The agent calls it when an answer depends on who is asking, and it receives the attributes a policy answer depends on.
  6. Shipped through a pipeline. GitHub Actions builds the container, pushes it to Azure Container Registry and deploys it to Azure Container Apps.

How it was tested

I owned the evaluation method. Answers were assessed for grounding and accuracy against the policy text.

My part and the team's

I led development and launch, owned retrieval design, citation and grounding behaviour and the evaluation method, and built the backend for the next version and its MCP server. HR owned the policy content.

Under the hood
  • Launch stack: Copilot Studio, Teams, SharePoint knowledge, Dataverse.
  • Next version: an Azure AI Foundry agent behind a FastAPI service, with JWT auth, SSE streaming, container images in Azure Container Registry, and Azure Container Apps.
  • The MCP server exposes employee context to the agent as a tool.
